## Circularity 0.6.0

### Watched folders
- **Pick a folder, and every new file that lands in it is converted on its own**, as if you'd dropped it on that button. Use any format, or one of your own resize or compress buttons. **Convert to JPG** for a Screenshots folder is a good one.
- It's in **Settings → Features → Watched folders**. Each folder can include its subfolders, and can be paused.
- It waits until a file has finished arriving, so big downloads and copies are fine. Partial downloads, files that were already there, and Circularity's own results are left alone, even when results are saved into the same folder.

### Undo last conversion
- **Converted the wrong thing?** Use **Undo last conversion** in the tray menu, or **Undo** on the "Done" notification. That conversion's results go to the Recycle Bin, so you can still get them back.
- Only the most recent conversion can be undone. A result you've changed since is left alone, and your originals are never touched.

### A roomier wheel
- **When More has lots of buttons, they open on two arcs** instead of being squeezed into one. The first arc holds five; past that, a second, wider arc opens around it for up to six more. The buttons stay the same size, and every label fits.
- **The wheel shows at most 16 buttons.** If you have more, the ones you use least (or put last) are left off, and **Settings → Buttons** says which ones don't fit. Buttons that open a window, like Crop, are always kept.
- **The middle of the wheel now says what the button you're on does**, such as "Convert to WEBP" or "Crop…".
- **The wheel adapts to how you use it.** The buttons you use most move to the front, onto the ring. It's on by default, in **Settings → Buttons → Adapt to how you use it**. If you set your own order there, your order wins.
- **BMP and TIFF are hidden by default**, since few people need them. Turn them back on in **Settings → Buttons**.

### Install
Download **CircularitySetup-0.6.0.exe** below and run it, or use **Check for updates** in the tray menu if you already have Circularity.

Windows may show a SmartScreen warning because the installer isn't code-signed: click **More info → Run anyway**.

## For developers

**Watched folders** (`Engine/FolderWatcher.cs`, `Settings.WatchedFolders`, `SettingsWindow`)
- `WatchedFolder(Id, Path, Action, IncludeSubfolders, Enabled)` is saved in settings. `Action` is a target (`"jpg"`) or `"preset:<id>"`, the same IDs as wheel buttons. `OperationFor(settings)` returns null for a deleted preset, which Settings shows as "(a deleted preset)" and the app skips.
- There is one `FileSystemWatcher` per enabled folder, on `Created` and `Renamed` (a finished download is renamed from `.crdownload`/`.part`). `Update()` keeps watches whose record hasn't changed, and replaces or stops the rest.
- A candidate must have a known file type and must not be a directory, hidden, system, temporary, `~`- or `.`-prefixed, or a partial download. It is reported once its size and time have stayed the same for a second and it opens with `FileShare.None`, or it is dropped after 30 minutes. Files arriving within 2 seconds of each other become one batch.
- Loops are prevented by `OutputPaths.IsProduced`. Every reserved output file and folder is recorded before it's created, so the watcher already knows a result when it sees it appear, including pages inside a "(pages)" folder. If creating it fails, the record is removed again, so a file Circularity didn't write is never skipped.
- `App.OnWatchedFilesArrived` re-checks that the folder is still in Settings, then queues the files that `Formats.Suits` (the type is offered that conversion, or the preset's tool and kind match) and that a converter can handle. Anything else is logged and skipped.
- In Settings each folder takes two lines: the on/off box, its name and full path, and remove; then the action and "Subfolders too".

**Undo** (`UndoLastConversion.cs`, `FinishedToast.Undo`)
- Every batch with successes replaces the undo record with its outputs, each with its size and write time (for a folder of pages: file count and newest write time).
- `Undo()` sends unchanged results to the Recycle Bin with `Microsoft.VisualBasic.FileIO.FileSystem`. Changed ones are kept, and missing ones are counted as gone. The record is then cleared, so it works once.
- The toast's Undo button carries the first output's path. It only undoes while that path is still in the record, so an old notification can't undo a newer conversion. After a restart there's nothing to undo, and the notification says so.

**The two-arc wheel** (`WheelView`)
- The first arc takes up to `FirstArcMax` (5) buttons in order, and only past that does `SplitRows` open a second row for the rest, up to `SecondArcMax` (6). `_arcTargets` lists the inner row first.
- `WheelView.Layout` caps the arcs at `MaxArcButtons` (11). It leaves off ordinary buttons from the end of the order, never a dialog button, and Settings → Buttons marks those "Doesn't fit".
- Each row is its own arc. The second starts at `FirstArcEdge`, the first arc's outer edge, with the same inset inside each, and is drawn as a separate band with all four corners rounded. Hit-testing picks the row by radius, then the button by angle within that row's span.
- The second row's buttons are the same width in pixels as the first's, so fewer degrees each. `Extent` and `ArcReach` always allow for two rows, so the window never resizes mid-drag, and a drag that starts near the bottom of the screen flips upwards in time.
- `FitLabels` picks one label size per row (the ring, or one arc): the usual size, or as small as 70% (never under 8.5 px) so the widest label fits. Anything still too wide wraps to two lines, and only then gets "…".
- While a button is lit, the centre shows `WheelView.Describe(action)` in place of the file name, the same way it shows "Cancel" over the centre.

**Button order** (`Formats`, `Settings`, `App.CountUse`)
- `Settings.AdaptToUse` (default true) and `Settings.UseCounts`, which maps kind to button ID to count. `App.CountUse` adds one each time a button is chosen for files of one kind, and saves.
- `Formats.Ordered` uses the user's own order if they've set one. Otherwise, with adapting on, it sorts by count, highest first, keeping the built-in order for ties and unused buttons. Otherwise it keeps the built-in order. Mixed selections aren't reordered.
- `Formats.DefaultLayout` hides `bmp` and `tiff` for images until the kind has a layout of its own. A layout created in Settings starts from the default, so unhiding one format doesn't bring back the other.
- The Settings window copies the app's `UseCounts` back on every change, so its own copy never overwrites newer counts.

**Tests**
- Button order: BMP and TIFF are hidden by default and shown once the image layout is changed; adapting puts the most used first; turning it off keeps the built-in order; your own order wins; counts are per kind, copied by `Clone`, and survive saving.
- `--render-previews` adds `wheel-crowded` and `wheel-crowded-above`: every image format and four saved buttons.
- Watched folders and undo:
  - undo removes once and leaves changed or gone results alone;
  - only the newest results are undoable, and a folder of pages can be undone;
  - preset actions resolve, and a deleted preset resolves to nothing;
  - broken watched-folder entries are dropped;
  - `Suits` handles conversions and presets;
  - outputs are remembered, but a taken name isn't;
  - the watcher skips partial, hidden, unknown and own files, reports renamed downloads, batches new files and ignores old ones, watches subfolders only when asked, and stays quiet when paused.
- A new end-to-end smoke check: a picture copied into a watched folder is converted, and its result, saved into the same folder, isn't converted again.
