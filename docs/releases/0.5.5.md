## Circularity 0.5.5

### Update checks and a daily usage count, on by default
- **Circularity now checks for updates on its own**, at the interval set in Settings, so you hear about fixes without having to look.
- **It also sends one anonymous count a day**, so I know how many people actually use it. The count is a random ID and the version number, nothing else: no files, file names, folders, or account or computer names. The ID isn't tied to you. Turning the count off deletes it, and turning it back on makes a new one.
- **Both can be turned off** in **Settings → Features**. New installs can also untick the count on the welcome screen.
- **The first time you start 0.5.5**, a notification says this. Click it to go straight to the setting.
- The README's [Privacy](https://github.com/AtharvGogia/Circularity-for-Windows#privacy) section explains exactly what's sent and where. The server code is public too.

### Install
Download **CircularitySetup-0.5.5.exe** below and run it, or use **Check for updates** in the tray menu if you already have Circularity.

Windows may show a SmartScreen warning because the installer isn't code-signed: click **More info → Run anyway**.

## For developers

**What's sent** (`UsagePing.cs`)
- A `POST` to `https://circularity-usage.gogiaatharv.workers.dev/ping` with the body `{"id":"<guid>","version":"x.y.z"}`, and the same `Circularity/<version>` User-Agent as the update check. It has a 30-second timeout, and failures are logged and dropped.
- `IsDue(last, todayUtc)` is true when there's no previous ping, or when the last one was on another day. That includes a date in the future, which happens when the clock has been set back.
- `App` schedules a first try 2 minutes after start, then one every 6 hours, so a PC left on overnight still counts the next day. `LastUsagePing` is saved only after a successful send, and only if the count is still on with the same ID. No ping is sent while the welcome window is open.

**Settings** (`Settings.cs`, `Version` 3)
- New fields: `ShareUsageCount` (default true), `UsageId`, `LastUsagePing` (`yyyy-MM-dd`, UTC) and `UsageNoticeShown`. `AutoCheckForUpdates` now defaults to true.
- The v2 to v3 migration turns on both `AutoCheckForUpdates` and `ShareUsageCount`. Every older file stores `AutoCheckForUpdates: false` because defaults are written out, so a stored false can't be told apart from a deliberate choice. A v3 file keeps whatever it says.
- `SetShareUsageCount(bool)` keeps the ID rules in one place. Turning the count on creates a fresh GUID, and turning it off clears `UsageId` and `LastUsagePing`.

**Server** (`server/usage`, new)
- A Cloudflare Worker with a D1 database, built with the `cf` CLI. `POST /ping` rejects bodies over 200 bytes, checks the GUID and the `x.y.z` version, and runs `INSERT OR IGNORE` into `pings(day, id, version)`, keyed by `(day, id)`.
- The day comes from the server's UTC clock, so a wrong PC clock can't count someone twice. The Worker never reads the IP address or other headers.
- `GET /stats` returns `{today, last7, last30, versions}`, and `GET /badge` returns the same count in the shields.io endpoint format. A daily cron deletes rows older than 90 days.

**CI releases** (`.github/workflows/ci.yml`)
- Pushing a `v*` tag now builds the installer on the runner and publishes the release. This is the first release built that way. The tag must match `<Version>` in `Circularity.csproj`, and the notes are read from `docs/releases/<version>.md`.
- The slim FFmpeg is built with the runner's MSYS2 and cached until its build scripts change. Inno Setup is installed with Chocolatey if it's missing.
- The installer job can also be run by hand with `workflow_dispatch`, which builds the installer and uploads it as an artifact without releasing it.

**Tests**
- Unit tests cover the v2 to v3 migration, a v3 file with both options off staying off, a fresh `{}` file getting a `UsageId`, a new ID after turning the count off and on, and the `IsDue` cases (96 in total).
- Five new smoke checks use a fake HTTP handler (122 in total). They cover:
  - the POST going to the right URL;
  - the body having exactly `id` and `version`;
  - a 500 response returning false;
  - a throwing handler returning false without the exception escaping.
