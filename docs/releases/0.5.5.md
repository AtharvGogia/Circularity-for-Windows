## Circularity 0.5.5

### Watched folders
- **Pick a folder, and every new file that lands in it is converted on its own**, as if you'd dropped it on that button. Use any format, or one of your own resize or compress buttons. **Convert to JPG** for a Screenshots folder is a good one.
- It's in **Settings → Features → Watched folders**. Each folder can include its subfolders, and can be paused.
- It waits until a file has finished arriving, so big downloads and copies are fine. Partial downloads, files that were already there, and Circularity's own results are left alone, even when results are saved into the same folder.

### Undo last conversion
- **Converted the wrong thing?** Use **Undo last conversion** in the tray menu, or **Undo** on the "Done" notification. That conversion's results go to the Recycle Bin, so you can still get them back.
- Only the most recent conversion can be undone. A result you've changed since is left alone, and your originals are never touched.

### Update checks, and an optional usage count
- **New installs check for updates on their own**, at the interval set in Settings, so you hear about fixes without having to look. If you already had Circularity, this stays the way you had it: turn it on in **Settings → Features** if you'd like it.
- **You can now help count how many people use Circularity.** It's **off unless you turn it on**, on the welcome screen or in **Settings → Features**. If you do, it sends one anonymous count a day: a random ID and the version number, nothing else. No files, file names, folders, or account or computer names. The ID isn't tied to you. Turning the count off deletes it, and turning it back on makes a new one.
- The README's [Privacy](https://github.com/AtharvGogia/Circularity-for-Windows#privacy) section explains exactly what's sent and where. The server code is public too.

### Resize fixes
- **Fit with background** is no longer offered for videos, where it quietly just fitted the video without any background. It's still there for pictures.
- **Gradient backgrounds now come out the way the preview shows them.** Before, the saved picture could run the opposite way to the preview. If you saved a gradient preset with an angle, it now matches its preview, so check that it still looks the way you want.

### Install
Download **CircularitySetup-0.5.5.exe** below and run it, or use **Check for updates** in the tray menu if you already have Circularity.

Windows may show a SmartScreen warning because the installer isn't code-signed: click **More info → Run anyway**.

## For developers

**Watched folders** (`Engine/FolderWatcher.cs`, `Settings.WatchedFolders`, `SettingsWindow`)
- `WatchedFolder(Id, Path, Action, IncludeSubfolders, Enabled)` is saved in settings. `Action` is a target (`"jpg"`) or `"preset:<id>"`, the same IDs as wheel buttons. `OperationFor(settings)` returns null for a deleted preset, which Settings shows as "(a deleted preset)" and the app skips.
- There is one `FileSystemWatcher` per enabled folder, on `Created` and `Renamed` (a finished download is renamed from `.crdownload`/`.part`). `Update()` keeps watches whose record hasn't changed, and replaces or stops the rest.
- A candidate must have a known file type and must not be a directory, hidden, system, temporary, `~`- or `.`-prefixed, or a partial download. It is reported once its size and time have stayed the same for a second and it opens with `FileShare.None`, or it is dropped after 30 minutes. Files arriving within 2 seconds of each other become one batch.
- Loops are prevented by `OutputPaths.IsProduced`. Every reserved output file and folder is recorded before it's created, so the watcher already knows a result when it sees it appear, including pages inside a "(pages)" folder.
- `App.OnWatchedFilesArrived` re-checks that the folder is still in Settings, then queues the files that `Formats.Suits` (the type is offered that conversion, or the preset's tool and kind match) and that a converter can handle. Anything else is logged and skipped.

**Undo** (`UndoLastConversion.cs`, `FinishedToast.Undo`)
- Every batch with successes replaces the undo record with its outputs, each with its size and write time (for a folder of pages: file count and newest write time).
- `Undo()` sends unchanged results to the Recycle Bin with `Microsoft.VisualBasic.FileIO.FileSystem`. Changed ones are kept, and missing ones are counted as gone. The record is then cleared, so it works once.
- The toast's Undo button carries the first output's path. It only undoes while that path is still in the record, so an old notification can't undo a newer conversion. After a restart there's nothing to undo, and the notification says so.

**What's sent** (`UsagePing.cs`)
- A `POST` to `https://circularity-usage.gogiaatharv.workers.dev/ping` with the body `{"id":"<guid>","version":"x.y.z"}`, and the same `Circularity/<version>` User-Agent as the update check. It has a 30-second timeout, and failures are logged and dropped.
- `IsDue(last, todayUtc)` is true when there's no previous ping, or when the last one was on another day. That includes a date in the future, which happens when the clock has been set back.
- `App` schedules a first try 2 minutes after start, then one every 6 hours, so a PC left on overnight still counts the next day. `LastUsagePing` is saved only after a successful send, and only if the count is still on with the same ID. No ping is sent while the welcome window is open, so unticking its checkbox always wins.

**Settings** (`Settings.cs`, still `Version` 2)
- New fields: `ShareUsageCount` (default **false**), `UsageId` and `LastUsagePing` (`yyyy-MM-dd`, UTC).
- `AutoCheckForUpdates` now defaults to true, which only affects new settings files: older files store their `false` and keep it.
- No migration changes anything. An opt-in count needs none, and every older file has `AutoCheckForUpdates` written out, so leaving it alone keeps whatever the user had.
- `SetShareUsageCount(bool)` keeps the ID rules in one place. Turning the count on creates a fresh GUID, and turning it off clears `UsageId` and `LastUsagePing`.
- The welcome window's checkbox starts unticked, and whatever it says when the window closes is saved.

**Server** (`server/usage`, new)
- A Cloudflare Worker with a D1 database, built with the `cf` CLI. `POST /ping` rejects bodies over 200 bytes, checks the GUID and the `x.y.z` version, and runs `INSERT OR IGNORE` into `pings(day, id, version)`, keyed by `(day, id)`.
- The day comes from the server's UTC clock, so a wrong PC clock can't count someone twice. The Worker never reads the IP address or other headers.
- `/ping` goes through a rate-limit binding (`PINGS`, 60 a minute) with one shared key rather than one per address, so no IP is read. That is far above real traffic and keeps a flood under D1's free daily writes. A refused ping gets a 429, and the app tries again later.
- `GET /stats` returns `{today, last7, last30, versions}`, and `GET /badge` returns the same count in the shields.io endpoint format. Both are served from `caches.default` for 5 minutes once the Worker is on a custom domain. On `workers.dev` the Cache API is a no-op, so for now they still query D1 on every request. A daily cron deletes rows older than 90 days.

**Resize** (`Operations.cs`, `ImageConverter.cs`, `FfmpegConverter.cs`, `ResizeDialog`)
- `ResizeBackground.GradientPoints()` is now the only place the gradient's geometry is worked out. Both the dialog's preview brush and the saved image use it.
  - 0° runs left to right, and the angle turns anticlockwise.
  - A spec with only a legacy `GradientDirection` (angle 0, not horizontal) draws as before.
- `FfmpegConverter.CanHandle` refuses `ResizeTo` with `FitWithBackground`, since the slim FFmpeg has no `pad` or `overlay` filter. That also keeps such presets off a video's wheel. The dialog hides the mode when any of the files is a video.

**CI releases** (`.github/workflows/ci.yml`)
- Pushing a `v*` tag builds the installer on the runner and publishes the release. This is the first release built that way. The tag must match `<Version>` in `Circularity.csproj`, and the notes are read from `docs/releases/<version>.md`.
- The slim FFmpeg is built with the runner's MSYS2 and cached until its build scripts change. Inno Setup is installed with Chocolatey if it's missing.
- The installer job can also be run by hand with `workflow_dispatch`, which builds the installer and uploads it as an artifact without releasing it.

**Tests**
- Watched folders and undo:
  - undo removes once and leaves changed or gone results alone;
  - only the newest results are undoable, and a folder of pages can be undone;
  - preset actions resolve, and a deleted preset resolves to nothing;
  - broken watched-folder entries are dropped;
  - `Suits` handles conversions and presets;
  - outputs are remembered, but a taken name isn't;
  - the watcher skips partial, hidden, unknown and own files, reports renamed downloads, batches new files and ignores old ones, watches subfolders only when asked, and stays quiet when paused.
- A new end-to-end smoke check: a picture copied into a watched folder is converted, and its result, saved into the same folder, isn't converted again.
- Other new unit tests cover:
  - older files keeping update checks off, with the count staying off;
  - choices to turn things off being kept;
  - fresh settings checking for updates but not counting;
  - a new ID after turning the count off and on;
  - the `IsDue` cases;
  - the gradient points;
  - videos refusing a background.
- Smoke checks use a fake HTTP handler. They cover:
  - the POST going to the right URL;
  - the body having exactly `id` and `version`;
  - a 500 response returning false;
  - a throwing handler returning false without the exception escaping.
