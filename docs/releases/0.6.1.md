## Circularity 0.6.1

### Safer with files from elsewhere
- **Office documents can't run macros when they're converted.** Word, Excel and PowerPoint are told to turn macros off before a document is opened, and put back as they were afterwards.
- **HTML and Markdown are turned into PDFs offline, with no scripts.** A page can't reach the internet (not even its pictures or styles from the web) or run its own code while it's being laid out. Pictures and styles beside it on your PC still work. A page that won't finish loading is given up on after 30 seconds, and **Cancel conversions** now stops it.

### Photos keep their details
- **Converting, resizing, cropping or compressing a photo keeps its details**: when and where it was taken, the camera and its settings, and its author, title, keywords and rating. JPEG and TIFF results keep all of these. Results also keep the photo's colour profile, so an iPhone's richer colours (Display P3) don't come out duller.
- **Photos stored mirrored now come out the right way round**, as well as rotated ones.

### Fixes
- **Holding Shift (or right-clicking) while selecting no longer opens the wheel.** It only opens while you're dragging something: a file, a link or a picture. Shift-clicking to select text, drawing a selection box in File Explorer, and moving a window with Shift held (as FancyZones does) work as usual again.
- **Watched folders on a USB stick or network drive start working when the drive comes back.** If a watched folder isn't there (when you sign in, say) or goes away, Circularity looks for it again every 30 seconds.
- **Your settings can't be lost to a crash or power cut mid-save.** If a settings file ever can't be read, it's kept beside the new one as "settings (unreadable …).json" instead of being replaced by the defaults.
- **The "daily users" badge on the website no longer drops to zero at midnight (UTC).** It shows the busier of yesterday and today so far.

### Install
Download **CircularitySetup-0.6.1.exe** below and run it, or use **Check for updates** in the tray menu if you already have Circularity.

Windows may show a SmartScreen warning because the installer isn't code-signed: click **More info → Run anyway**.

## For developers

**Office macros** (`Engine/OfficeConverter.cs`)
- Each app's `AutomationSecurity` is set to `msoAutomationSecurityForceDisable` (3) before the document is opened and put back in `finally`. Office's default for a program driving it is "low" (macros run), which this PC confirmed for Word and Excel. Office's block on macros in downloaded files still applied before, so the gap was files without that mark (USB sticks, shares, some unzip tools) and the old `.doc`, `.xls` and `.ppt` formats.

**Printing pages to PDF** (`Engine/WebPdfConverter.cs`)
- `LockDown` turns off scripts, script dialogs, web messages, DevTools and context menus. A `WebResourceRequested` filter on `*` answers anything that isn't `file:`, `data:`, `blob:` or `about:` with a 403, and `NavigationStarting` cancels any navigation except the page being printed (a `<meta http-equiv="refresh">`, say).
- The WebView2 environment is created with `--proxy-server=127.0.0.1:1 --proxy-bypass-list=<-loopback>`. The request filter alone let the browser open a connection early (its preconnect), before the page's requests were made: a test server saw the connection, with no request on it. Every connection, loopback included, now goes to a proxy that isn't there.
- Loading waits at most 30 s and printing 90 s, and both take the job's cancellation token. On a timeout or cancel the controller is closed and the next print makes a new one, so a stuck page can't hold the single print slot (and with it, the queue's workers).
- A new smoke check prints a page with a script, a meta refresh to another page, and a stylesheet, picture and frame from a server on this PC that counts connections. The PDF has the page's text, not the script's or the other page's, and the server is never contacted.

**Photo details** (`Engine/ImageConverter.cs`)
- `Load` returns the upright picture with a `PhotoDetails`: the frame's metadata (cloned and frozen while the file is open, since the original reads from the file lazily) and its colour contexts. `LoadOriented` is `Load(...).Image`.
- `Encode` saves JPEG and TIFF with `OutputMetadata` and JPEG, PNG and TIFF with the colour profile. If the encoder rejects either, it logs that and saves the picture without them.
- `OutputMetadata` builds new metadata rather than cloning the old, so the old EXIF thumbnail (which would show the uncropped picture) isn't carried over. It copies the EXIF and GPS sub-IFDs as blocks (`/app1/ifd` for a JPEG source, `/ifd` otherwise), then the named fields Windows can move between formats (date taken, camera make and model, application, author, copyright, title, subject, comment, keywords, rating). It sets orientation (274) to 1, and the EXIF pixel size (40962/40963) to the result's when present.
- Not covered: GPS from a HEIC into a JPEG (only the named fields cross over from HEIC), WebP and AVIF results (FFmpeg encodes them from a PNG), HEIC results, and PDFs. Not tested on a real iPhone HEIC, as there wasn't one on this PC.
- `Upright` handles all eight EXIF orientations, the mirrored ones (2, 4, 5, 7) included, and `ReadSize` swaps the sides for 5 to 8.

**The gesture** (`App.Input.cs`)
- `ShouldArm` first checks `IsFileDrag`: `GetGUIThreadInfo` for the foreground window's thread. While OLE carries a drag, the mouse is captured by OLE's own window, class `CLIPBRDWNDCLASS`; while an app follows the mouse itself (text selection, a selection box, a tab drag), its own control holds the capture. Moving or sizing a window (`GUI_INMOVESIZE`) and an open menu (`GUI_INMENUMODE`) are refused too. With no capture visible it arms, as before.
- This was measured first, in a probe window that drew a selection box, selected text and did a real file drag: the capture classes were the panel, the edit box and `CLIPBRDWNDCLASS`. The cursor couldn't tell them apart: it's the plain arrow for a selection box, which Explorer's own drags show as well.
- Checked live against the dev build's hook, with Shift pressed during each: the selection box and the text selection were let through ("the left button isn't dragging something"), and the file drag passed this check.
- `App.ArmsFor(flags, captureClass)` is the rule on its own, for the tests.

**Watched folders** (`Engine/FolderWatcher.cs`)
- `Update` keeps a watch even if its folder can't be watched yet. Each watch has a timer (`retryEvery`, 30 s) that starts the `FileSystemWatcher` once the folder is there, or drops it when the folder has gone.
- A watcher `Error` other than a buffer overflow (the folder deleted, the drive unplugged, the share gone) drops that watcher and tries again at once, then on the timer. A buffer overflow is logged and the watcher carries on. The first failure and the recovery are logged, not every retry.
- Files that arrive while a folder is missing are left alone when it comes back, like files that were there before watching started.

**Settings** (`Settings.cs`)
- `Save` writes to `settings.json.<guid>.tmp` with write-through and a flush to disk, then moves it over `settings.json`. `Load` moves a file that isn't valid JSON (an empty one included) aside as `settings (unreadable yyyy-MM-dd HH-mm-ss).json`, so saving the defaults can't overwrite it. `Load(path)` and `Save(path)` are there for the tests.

**Usage Worker** (`server/usage`)
- `/stats` adds `yesterday`, and `/badge` shows `max(today, yesterday)`.

**Tests**
- Photo details: resize, crop, compress and convert to TIFF keep the date taken, camera, GPS, colour profile and EXIF size, and are marked upright. All eight orientations come out upright with the right size, and a picture without details still converts. 7 of these 13 fail on 0.6.0.
- Settings: saving leaves no temporary files, and an unreadable or empty file is kept.
- Gesture: `ArmsFor` for a drag, nothing, a selection box, text selection, a window move and a menu.
- Watched folders: a folder that appears later is watched, and one deleted and made again is watched again (both fail on 0.6.0).
- 166 unit tests and 125 smoke checks pass, as do the drag, interaction and startup tests.
